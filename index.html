📖 health.log 사용법 — A to Z
📑 목차
준비 단계: A. 다운로드 → B. Ollama 설치 → C. CORS 설정 → D. 모델 다운로드 → E. 연동 확인
초기 설정: F. 첫 실행 → G. 개인 정보 입력 (키/체중/목표/GLP-1)
일상 사용: H. 매일 체중 → I. 식사 기록 → J. 운동 기록 → K. 수면/걸음 → L. 캘린더 검토
심화 분석: M. 검진 PDF 업로드 → N. 분석 trend → O. 근손실 방지 검증
관리: P. JSON 백업/복원 → Q. 트러블슈팅
A. 다운로드 + 압축 풀기
  1. health.log-portable.zip 다운로드
  2. 적당한 폴더에 압축 풀기 (예: ~/Documents/health.log/ 또는 ~/Downloads/health.log/)
  3. 폴더 안 index.html 더블클릭 → 브라우저에서 자동 열림
  4. URL 이 file:///...index.html 인지 확인
💡 안전: 매번 같은 폴더에서 열어야 localStorage 가 유지됨. 폴더 이동/이름 변경 시 데이터 리셋됨
B. Ollama 설치 (포터블 LLM)
macOS
brew install ollama
# 또는 https://ollama.com/download 에서 .dmg 다운로드 → 드래그 설치
ollama serve &  # 백그라운드 실행 (macOS 앱 실행 시 자동)
Windows
# https://ollama.com/download/windows → OllamaSetup.exe 다운로드 + 설치
# 설치 후 시스템 트레이 자동 실행 (재부팅해도 자동시작)
Linux
curl -fsSL https://ollama.com/install.sh | sh
systemctl --user start ollama  # 또는 ollama serve &
C. ⚠ OLLAMA_ORIGINS 설정 (file:// 필수)
file:// 에서 Ollama 호출하려면 CORS 허용 필수. 미설정 시 분석 버튼 클릭해도 network error.
macOS (영구 설정)
launchctl setenv OLLAMA_ORIGINS "*"
osascript -e 'tell app "Ollama" to quit'
open -a Ollama  # 재시작 필수
Windows (PowerShell 관리자)
[Environment]::SetEnvironmentVariable("OLLAMA_ORIGINS", "*", "User")
# Ollama 트레이 아이콘 우클릭 → Quit → 재시작
Linux
echo 'export OLLAMA_ORIGINS="*"' >> ~/.bashrc
source ~/.bashrc
systemctl --user restart ollama
💡 보안: "*" 대신 "file://*,http://localhost:*" 권장
D. 모델 다운로드 (vision 지원 필수)
# 권장 (cloud, Ollama 계정 필요, 한국어 강함)

# 완전 오프라인 옵션 (19GB)
ollama pull gemma3:27b

# 경량 옵션 (GPU 8GB 이하)
ollama pull llama3.2-vision:11b

E. 연동 확인
  1. 터미널: curl http://localhost:11434/api/tags → 200 + 모델 목록 응답
  2. 브라우저: index.html 새로고침 (F5)
  3. 📸 식단 스캔 탭 → 음식 사진 1장 업로드 → 🤖 AI 분석 실행
  4. "분석 완료" 토스트 = ✓ 정상. "network error" = OLLAMA_ORIGINS 재확인
F. 첫 실행 — 초기 상태
처음 열면 모든 데이터 비어 있음 (체중·식사·검진·운동 모두 0). 헤더 표시 — kg / BMI —. 각 탭이 데이터 입력을 기다림.
G. ⚙️ 설정 — 개인 정보 입력
⚙️ 설정 버튼 클릭 → 입력:
  • 📏 키 (cm) — BMI/BMR 계산 필수
  • 시작 체중 (kg) — 감량 추이 기준점
  • 목표 체중 (kg) — 진행률 계산
  • 일일 목표 (단백질·칼로리·수분·식이섬유) — 메인 탭 누적 비교
  • 💊 GLP-1 약물 (마운자로/위고비/기타/없음) — 위장 정체 경고 활성 분기
  • 📦 이미지 저장 방식 (임베드 = 단일 JSON 백업 / 경로 = 가벼움)
H. 매일 체중 입력
헤더 ⚖️ 체중 → 날짜 + kg → 저장. 또는 ⚖️ 체중 로그 탭에서 직접. 자동 갱신: BMI / LBM (체지방률 있을 때) / BMR (Mifflin·Katch·InBody 3공식) / TDEE / 권장 섭취 / 근손실 방지 최소 기준.
I. 식사 기록
📊 메인 탭 → 끼니 선택 (아침/점심/저녁/간식) → 직접 입력 또는 즐겨찾기 클릭.
📸 식단 스캔 탭 → 음식 사진 + 영양성분표 + 메모 → AI 분석 → 검토 + 끼니 추가.
일자 선택으로 과거 기록 backfill 가능.
J. 운동 기록
🏋️ 운동 스케줄 탭 → 일자/종류/시간/RPE (0-10) → 추가. RPE 슬라이더 = modified Borg CR-10 (애플 피트니스 강도와 동일 스케일).
K. 피트니스 (걸음/소모칼로리) + 수면
📊 메인 탭 아래 피트니스/수면 영역 → 일자 picker + 직접 입력 또는 📸 스크린샷 AI 분석 (애플 피트니스 / AutoSleep). 기본값 어제 (운동/수면 기록은 보통 어제 기준).
L. 📅 캘린더 검토
일별 평가 색상: 운동 + 칼로리 목표 이하 = 초록 ✨ / 칼로리 초과 = 빨강 / 부분 기록 = 회색. 셀 클릭 → 상세 모달 (끼니/운동/체중/수면).
M. 🩺 검진 PDF AI 분석 (핵심 기능)
  1. 🩺 건강검진 탭 → 상단 AI 분석 카드
  2. 검진 PDF 파일 선택 (다중 파일 OK, 페이지별 이미지 자동 변환)
  3. 🔒 암호 PDF 면 자동 모달 표시 → 비밀번호 입력 (최대 3회)
  4. 또는 텍스트 직접 paste / 추가 설명 입력
  5. 🤖 AI 분석 실행 버튼 → Ollama 호출 (수십 초 ~ 수 분)
  6. JSON 결과 preview → 직접 편집 가능 → ✅ 적용 → 화면 갱신
💡 검진 자료 적용 후: 체중 로그의 LBM/Katch BMR/InBody BMR 모두 정확한 값으로 자동 갱신. 의심 질환은 카테고리 자동 분류 (이상지질혈증/고혈압/지방간 등)
N. 📈 분석 페이지 (trend)
14일 단백질/칼로리/걸음 + 4주 운동 볼륨 (RPE × 분) trend bar. 의료 일정 리마인더 자동 시드.
O. 💪 근손실 방지 최소 기준 검증
⚖️ 체중 로그 탭 하단 카드 — ISSN 2017 가이드 + GLP-1 환경 기준:
  • 최소 칼로리: max(BMR, 1500) — 절대 한계
  • 안전 최저: BMR + 200 — 지속 가능
  • 단백질 최소/권장/상한: 1.6 / 2.0 / 2.4 g/kg 체중
  • 활동 수준 변경 시 권장 자동 재계산
  • 설정한 칼로리/단백질 목표가 안전 범위 밖이면 ⚠ 경고 표시
P. 💾 데이터 백업 / 복원
💾 JSON 저장 — 모든 데이터 (체중·식사·운동·검진 등) JSON 1개 파일로 export.
📂 불러오기 — 백업 JSON import. 다른 기기로 이전 시 사용.
포터블(file://) 은 localStorage 만 사용 → 주기적 JSON 백업 권장 (브라우저 캐시 클리어 시 데이터 손실).
Q. 🔧 트러블슈팅
❌ "network error" / "fetch failed"
→ OLLAMA_ORIGINS 미설정. C 단계 재확인 + Ollama 재시작
❌ "model not found"
→ ollama pull gemma4:31b-cloud + ollama list 확인
❌ 분석 결과 빈 JSON / 잘림
→ num_predict 부족. 검진/식단 prompt 별 자동 조정 (검진=8192, 식단=4096)
❌ 한국어 잘못 인식
→ llama3.2-vision 대신 gemma4:31b-cloud 사용
❌ 응답 지연 30초+
→ GPU 부족 가능. qwen2.5-vl:7b 같은 경량 모델 시도
🔒 암호 PDF 인식
→ 자동 모달 표시 → 비밀번호 입력 (3회 제한)
❌ 데이터 사라짐
→ localStorage 가 폴더 위치 기반. 폴더 이동/이름 변경 시 분리. JSON 백업 복원 가능
❌ 다기기 동기화 X
→ 포터블은 단일 브라우저 한정. 자체 호스팅 또는 JSON 수동 전송
❌ 본인이 아닌 데이터가 보임
→ 이전 사용자의 localStorage 잔존 가능. 브라우저 시크릿/프라이빗 모드로 열거나 DevTools → Application → Local Storage 클리어

→ 자동 변환 지원됨 (heic2any CDN). 첫 업로드 시 인터넷 필요 (이후 캐시). "HEIC → JPEG 변환 완료" 토스트 확인. 변환 실패 시 아이폰 설정 → 카메라 → 형식 → "높은 호환성" (JPEG) 으로 변경 권장
